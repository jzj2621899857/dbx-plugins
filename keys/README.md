## 密钥轮换说明（2026-10-20）

第一把密钥的私钥文件当时只存在于 `/tmp`，被系统清理后无法恢复，因此 0.2.0 起改用第二把密钥。

- 0.1.x 的包仍由旧密钥签名，旧公钥需要保留在信任列表里，否则已装的老版本会验签失败
- 0.2.0 及之后由新密钥签名
- **两把公钥都要信任**，才能同时加载新旧版本

## 如何信任这把公钥

**请通过与本仓库无关的渠道核对上面的值。** 如果你是从本项目 README 或仓库里直接复制这把公钥，那你只是信任了这个仓库本身——这仍然是可接受的（自建仓库的信任起点本来就是你），但要清楚自己在信任什么。

正式做法是由仓库运维把这段 Base64 通过另一个渠道（例如当面、聊天工具、你自己的私密笔记）发布出去，用户据此核对。

## 这把密钥证明什么

它证明：你安装的包字节，就是本仓库审核并签发的那些字节。它**不**证明作者无害——原生 sidecar 以你自己的用户权限运行，签名不是操作系统沙箱。

## 轮换

私钥若泄露或需要更换，按以下顺序操作：

1. 用同一 Key ID 生成新密钥（Key ID 不复用于不同公钥字节时，应改用新 ID，如下一条）
2. 新 Key ID 加入 `catalog` 与本文档，用新密钥开始签名
3. 等用户更新到支持新密钥的版本后，撤销旧 Key ID

私钥只存在于本机受保护环境与 CI 的加密 secret 中，永不提交到任何仓库。

## 本仓库不存放私钥

`.gitignore` 已排除 `*.env`、`*.key`、`*.seed`。如果在这里看到任何私钥材料，那是事故。
